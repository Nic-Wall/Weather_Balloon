
The module platform/ machine (`-M`) used is `virt`, since there aren't any specific changes that warrant running on anything except a general virtual machine. I know from [Pine64's Official Docs on the RockPro64](https://wiki.pine64.org/wiki/ROCKPro64#CPU_Architecture) the CPU architecture is Dual-core Cortex-A72 and Quad-core Cortex-A53. Since there is no GUI, it's all CLI, the `-nographic` option can be used. As this is just testing `-smp` (the number of virtual CPU's) only needs to be 1. Then the kernel, as created in [[4. Kernel]], needs to be added with `-kernel` and the `initramfs.cpio.gz` created in [[5. Root Filesystem]] with `-initrd`. Lastly, a few parameters to tell the kernel where to output the console (`console=ttyAMA0`) and tell the kernel what program to start after loading the initramfs (`rdinit=/bin/sh`), and in this test it's Busy Box's implementation of `sh` set in [[5. Root Filesystem]], `ash`. So...
```shell
pwd
# Returns...
/home/nicholas/Projects/WeatherBalloon/qemu

qemu-system-aarch64 \
-M virt \
-cpu cortex-a53 \
-nographic \
-smp 1 \
-kernel ../by_hand/build_arm64/arch/arm64/boot/Image \
-append "console=ttyAMA0 rdinit=/bin/sh" \
-initrd ../by_hand/initramfs.cpio.gz
```

The last command doesn't run because `sensorMonitor` doesn't have the permissions to run these commands. As much as I'd like to test booting into the `rootfs` with U-Boot on QEMU there is no emulated rockpro64-rk3399 machine (as far as I know) so I'd need to make another U-Boot bin for QEMU's virt.
This test is also using `/bin/sh` instead of my `rcS`, this is solved by changing the append to `console=ttyAMA0 rdinit=/sbin/init`.
To make generating the initramfs easier I made the following shell script (meant to be run from `/home/nicholas/Projects/WeatherBalloon/qemu`)...
```gen_initramfs.sh
#!/bin/bash
cd ../by_hand
pwd
rm initramfs.cpio.gz
rm uRamdisk
cd linux-stable
./usr/gen_initramfs.sh -o ../initramfs.cpio -u 1000 -g 1000 ../rootfs
cd ..
gzip initramfs.cpio
./u-boot/tools/mkimage -A arm64 -O linux -T ramdisk -d initramfs.cpio.gz uRamdisk
```
It's a little sloppy because it reports a failure to remove `initramfs.cpio.gz` and `uRamdisk` if they don't exist, but it works and it's easier than doing it by hand any time I make a change to `rootfs`.
Also, the organization is a bit of mess. Some `.configs` exist in the source directories, it's not easy to navigate to necessary binaries (U-Boot), and it doesn't allow for much modulation (U-Boot rockpro binaries and QEMU U-Boot binaries).
