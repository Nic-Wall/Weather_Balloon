After uploading to Github and attempting to work across two distributions (Arch (desktop) and Mint (later Void) (laptop)) I found building the project to be inconsistent, likely due to the mismatch in `gcc` versions. Largely, this would have little to no effect on a project like this except for the need to install dependencies like `bison` on every device in which one wishes to compile the project.
Therefore, the best course of action is to build out my own toolchain. One that can be installed and used in exactly the same manner across any device/ distribution.
The simplest option is to install a pre-made toolchain that matches all my requirements. It needs a compiler, a linker, and a list of runtime libraries. It also needs to be a cross-toolchain, since I'm compiling for an ARM SoC. In the books I've read (predominantly Mastering Embedded Linux) I've become most familiar with [Bootlin](https://toolchains.bootlin.com/releases_aarch64.html), so it's what I'll choose to use.
NOTE: It was at this point I swapped my install from Linux Mint to Void Linux. I performed this swap to get hands on learning with runit as I'm already familiar with systemd on my desktop machine. So some package dependencies may need to be installed again. These are my dirty/ learning notes, so everything goes in here!
The toolchain itself is downloaded from Bootlin [here](https://toolchains.bootlin.com/). The Mastering Embedded Linux book recommends using glibc unless one knows of a use case where uClinux is required or the storage of the device is below 32 MiB (in which case musl libc is recommended). Since I do not know of any instance where uClinux is required and the RockPro's board far exceeds the memory constraints musl libc works around, I chose glibc for the libc and aarch64 for the architecture. There is no need for me to use bleeding-edge as I can't think of a usecase in this project where it would be necessary, so I opted for stable.
I then confirmed the shasum provided by Bootlin for their aarch64--glibc--stable-2025.08-1.tar.xz via their provided link. The link showed a 256 shasum of...
```
dfb47eee874eef9e8a7fc042eee4e0a183f444b6bcde6a82fef8f009918389c9  aarch64--glibc--stable-2025.08-1.tar.xz
```
... then comparing to the one of the `.tar.xz` I downloaded...
```
$ cd ~/Downloads
$ shasum -a 256 aarch64--glibc-stable-2025.08-1.tar.xz
dfb47eee874eef9e8a7fc042eee4e0a183f444b6bcde6a82fef8f009918389c9  aarch64--glibc--stable-2025.08-1.tar.xz
```
They match!
The `README.txt` in the extracted tarball has directions on how to reproduce the toolchain...
```
git clone https://github.com/bootlin/buildroot-toolchains.git buildroot
cd buildroot
git checkout toolchains.bootlin.com-2025.08.1

curl http://toolchains.bootlin.com/downloads/releases/toolchains/aarch64/build_fragments/aarch64--glibc--stable-2025.08-1.defconfig > .config
make olddefconfig
make
make sdk
```
Then the tool chain is added to the path with...
```
$ PATH=$(pwd)/manual/crossCompiler/aarch64--glibc--stable-2025.08-1/bin/:$PATH
```
Now the path can be tested by finding the version with...
```
$ aarch64-buildroot-linux-gnu-gcc -v
```
It returns...
`gcc version 13.3.0 (Buildroot 2021.11-18033-g83947c7bb6)`
So it works!
Testing with the above commands recommended by Bootlin saw a failure due to my device not having a dependency, `wget` and `rsync`. Now I know to check for these before continuing with the `manual_compilation.sh` install script!
Though, running the above build script took some time (upwards of 10 minutes) on my machine, so I'll probably still opt for the download link.
