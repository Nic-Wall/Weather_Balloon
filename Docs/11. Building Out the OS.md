# Network Setup
The following network setup uses only what is available via BusyBox utilities. All that's really needed is a network interface, a few directories, and a handful of commands.
Firstly, the following directories need to exist in the staging directory...
- `etc/network`
- `etc/network/if-pre-up.d`
- `etc/network/if-up.d`
- `var/run`
Then, a network interface needs to be created at the file `etc/network/interfaces` with the following content...
```
auto lo
iface lo inet loopback
auto eth0
iface eth0 inet dhcp
```
Details on the syntax can be found at the following [StackExchange forum](https://unix.stackexchange.com/questions/128439/good-detailed-explanation-of-etc-network-interfaces-syntax) and [interfaces(5)](https://manpages.org/etc-network-interfaces/5).
Briefly...
- `auto lo`: Automatically starts the `lo` interface at boot
- `iface lo inet loopback`: `iface` selects the interface, `lo`, `inet` is the name of the address family the interface uses (`inet` is for TCP/IP) along with the method in which the interface should be configured `lo` (loopback)
- `auto eth0`: Creates and starts the Ethernet 0 interface at boot
- `iface eth0 inet dhcp`: Selects the `eth0` interface and configures it to `dhcp` (acquiring an IP address from a DHCP server). BusyBox provides a DHCP client program under `udchpcd`, which itself requires a script in `usr/share/udhcpc/default.script`. Thankfully, BusyBox provides a sane default simple script at it's source `busybox/examples/udhcp/simple.script`. So, it'll just be copied into the `rootfs`...
```
$ pwd
/home/nicholas/Projects/WeatherBallon/manual
$ mkdir -p rootfs/usr/share/udhcpc
$ cp busybox/examples/udhcp/simple.script rootfs/usr/share/udhcpc/default.script
```
The use of glibc also see's the need for a [`etc/nsswitch.conf`](https://www.man7.org/linux/man-pages/man5/nsswitch.conf.5.html). This man page also includes a sane default...
```etc/nsswitch.conf
passwd: compat
group: compat
shadow: compat

hosts: dns [!UNAVAIL=return] files
networks: nis [NOTFOUND=return] files
ethers: nis [NOTFOUND=return] files
protocols: nis [NOTFOUND=return] files
rpc: nis [NOTFOUND=return] files
services: nis [NOTFOUND=return] files
```
... and with it the need for a hosts file at `etc/hosts`...

## Addition of SSH ([DropBear](https://www.busybox.net/tinyutils.html))
I Googled around for an industry standard SSH implementation on embedded devices and pretty quickly found DropBear, a light-weight SSH server and client. Notably, since this device doesn't need to be a client, DropBear allows for server only compilation.
The install process should be relatively simple given I've already cloned and compiled software in this project so far.
Firstly, acquiring the project...
```
$ pwd
/home/nicholas/Projects/WeatherBalloon/manual
$ git clone https://github.com/mkj/dropbear.git
$ cd dropbear
$ mkdir install_location
```
DropBear's [install](https://github.com/mkj/dropbear/blob/main/INSTALL.md) and [small install](https://github.com/mkj/dropbear/blob/main/SMALL.md) documentation make some notable suggestions to configuration settings prior to compilation. I've marked the most important below, along with their configuration options... (the directions to find these other options can be found in DropBear's install docs, `./configure --help` lists them all)
- Firstly, telling the configuration script which architecture this will be compiled for...
```
--host=aarch64-linux-gnu
```
- Set the CROSS_COMPILER now...
```
CC=aarch64-buildroot-linux-gnu-gcc
```
- Since there are no headers in the embedded build this project will need to be built statically...
```
--enable-static
```
- As the [small install](https://github.com/mkj/dropbear/blob/main/SMALL.md) states, if the project is built statically it's likely one should wish to disabled zlib as well (to keep the size small)...
```
--disable-zlib
```
- Lastly, I'll disable the use of log files that will not be present in the embedded environment...
```
--disable-lastlog
--disable-utmp
--disable-utmpx
--disable-wtmp
--disable-wtmpx
```
These changes can be verified by reading the `config.log` and `config.h`.
Similarly, the compilation has a few options that need to be included given my embedded board's environment. There's the obvious use of `CROSS_COMPILE` but also a few others that enable the use of static compilation, since headers won't be present on the board...
- Keeping the build small, I'll only include what's necessary...
```
PROGRAMS="dropbear dropbearkey"
```
- Setting the temporary destination directory...
```
DESTDIR=$BUILD_DIR/dropbear/install_location
```
So the actual `make` is...
```
make PROGRAMS="dropbear dropbearkey" DESTDIR=$BUILD_DIR/dropbear/install_location install
```
But an error is received stating a missing `crypt()` function. A quick [Google search](https://github.com/mkj/dropbear/issues/143) shows I need `libxcrypt` compiled as well if I'm cross-compiling. So...

## Addition of SQLite
The industry standard is SQLite and I'm already familiar with it. SQLite can also be easily [interfaced with C/C++](https://sqlite.org/cintro.html), making the eventual programming poritions of this project easier. Lastly, more good news, SQLite comes with amalgamation files, allowing to be included in C/ C++ script when necessary. So there is no compilation of a separate program required, just an included header in the sensor program.
The amalgamation headers can be downloaded and unpacked from [SQLite's site](https://sqlite.org/download.html)...
```
$ wget https://sqlite.org/snapshot/sqlite-snapshot-202607312245.tar.gz
$ tar -xzf sqlite-snapshot-202607312245.tar.gz
$ rm -rf sqlite-snapshot-202607312245.tar.gz
```
... with the necessary headers inside `sqlite-snapshot-202607312245` as `sqlite3.c` and `sqlite3.h`.
