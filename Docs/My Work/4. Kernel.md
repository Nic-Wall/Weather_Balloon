# Picking and Cloning the Kernel
Since I have no need for newest features of the most up-to-date kernel. I chose to go with the current stable build. According to the [ROCKPro64 Hardware Compatibility](https://wiki.pine64.org/wiki/ROCKPro64_Hardware_compatibility) page the Mainline kernel is fairly stable, though many of these tests seem fairly outdated (v 5.16 and older), I believe the kernel is always backwards compatible, so a more recent stable build should work.
`linux-stable` was clone via...
```shell
pwd
# Returns...

ls
# Returns...

git clone git://git.kernel.org/pub/scm/linux/kernel/git/stable/linux-stable.git
```
The current version is...
```shell

```

# Modules (`M`) vs Statically Linked (`*`)
Upon re-reading a section of *Mastering Embedded Linux Development* I noticed...
> Part 1 - Chapter 4 - Configuring and Building the Kernel - When to use kernel modules
> "On the other hand, with embedded devices, the hardware and kernel configuration is usually known at the time the kernel is built; therefore, modules are not so useful. In fact, they cause a problem because they create a version dependency between the kernel and the root filesystem, which can cause boot failures if one is updated but not the other. Consequently, it is quite common for embedded kernels to be built without any modules at all."
> *Mastering Embedded Linux* by Frank Vasquez and Chris Simmonds

I'll choose to keep labels currently set to `M` as they are right now. Perhaps in the future, if necessary, I'll statically link them into the kernel. Though, I did feel the above was worth mentioning.

... then I can run...

Which reflects the change made in **General setup > Local version**!
U-Boot expects the kernel to be in either a self-extracting `zImage` file or a compressed `Image.gz`. I chose to compile with `Image.gz` because my board supports 64-bit...
```shell
cd ../linux-stable

lscpu | grep "CPU(s):"
# Returns...
CPU(s): 8

make -j8 ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- Image.gz O=../build_arm64
```
After the compilation is complete...
```shell
aarch64-linux-gnu-size ../build_arm64/vmlinux
# Returns...

14518651	5698327	 582296	20799274	13d5f2a	../build_arm64/vmlinux
```
The desired `Image.gz` is found at `../build_arm64/arch/arm64/boot/`. 
# Compiling the [Device Tree](https://docs.kernel.org/devicetree/usage-model.html#id2)
Necessary for the hardware to be described to the operating system, a device tree of the devices and hardware selected via labels in the `make menuconfig`. These `.dtb` and `.dtbo` files will reside in `../build_arm64/arch/arm64/boot/dts/rockchip`
```shell
cd ../linux-stable

make ARCH=arm64 dtbs CROSS_COMPILE=aarch64-linux-gnu- O=../build_arm64
```
# Compiling the Modules
Similarly, I need to compile modules (ending in `.ko`). I was warned modules default install location is the host system's `/lib/modules` so I'll create a new directory and target that as the place for the compiled `.o` files, which will then be linked (`.ko`), and installed...
```shell
mkdir ../in_tree_modules

make -j8 ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- INSTALL_MOD_PATH=/home/nicholas/Projects/WeatherBalloon/by_hand/in_tree_modules modules_install O=../build_arm64
```
Now the modules exist in the subdirectories under `../in_tree_modules/lib/modules` and are ready to be copied into the root file system upon its creation.
